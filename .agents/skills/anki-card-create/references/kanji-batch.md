# Пакет изображений кандзи и ручная проверка

Применяется, когда фактическая `.anki-repo/create.yaml` назначает `kanji_assets`
полю создаваемой заметки. Публичные команды и JSON принадлежат
`tools/asset-store/README.md`; здесь задана оркестрация. При расхождении проверь
`kanji-assets --help` и README владельца. Не заменяй отсутствующий API скриптом,
который меняет манифест или самостоятельно сравнивает изображения.

## Зависимости и исходный снимок

Назначенное обработчику поле потребляет медиассылки. Символы для получения
берутся из сохранённого семантического `surface` новой заметки по явному
сопоставлению в [SKILL.md](../SKILL.md), а не из ещё пустого поля результата.
Выдели поддерживаемые кандзи, исключи kana и дедуплицируй между заметками.

Перед `batch start` проверь `.asset-store/kanji` через `kanji-corpus-gate` и
сохрани полный JSON владельца:

```bash
cargo run --locked --bin kanji-assets -- --output json list
```

Снимок записей берётся из `assets[]`: оставь `to_state = verified` и
`effective_status = verified`, сохрани `identity`, `sha256`, `human_decision`,
`validator`, `validation_status` и `evidence` для сравнения доверия.
Не разбирай манифест самостоятельно. Только при фактическом отсутствии каталога
и корпуса разрешён пустой снимок: `list` отдаёт ненулевой код,
`outcome = blocked`, `error.code = store_missing`. Другой отказ чтения закрывает
продолжение работы. Снимок неизменен при возобновлении; сам корпус — локальное
состояние рабочей копии и через Git не публикуется.

## Запуск и возобновление

Состоянием пакета и точными байтами кандидатов владеет `kanji-assets` под
`.asset-store/kanji/.runtime/batches/<batch-id>/`. Сохраняй ID вне `decks/**`
и Git. Повтор того же ID возобновляет исходный набор идентичностей и валидатор;
другой набор под существующим ID отвергается.

Запускай команды из корня checkout; отдельного бинарника в `PATH` нет:

```bash
# Создать пакет; без --batch-id владелец выдаст ID.
cargo run --locked --bin kanji-assets -- --output json batch start 漢 字

# Пройти до пяти новых раундов по всему текущему набору.
cargo run --locked --bin kanji-assets -- --output json batch run --batch-id <id>

# Прочитать сохранённое состояние и результаты.
cargo run --locked --bin kanji-assets -- --output json batch status --batch-id <id>
```

`batch start` переиспользует ресурсы с текущим итоговым доверием; повторное
получение их байтов не требуется. `batch run` завершает весь текущий раунд
перед следующим: повтор одной неразрешённой идентичности не опережает первую
попытку соседней. Ошибки отдельных элементов сохраняют успешные результаты.
После прерывания повторный `run` перечитывает состояние и продолжает работу.
Браузерное получение kanji и pitch запускай последовательно.

Ответ содержит `batch_id`, `counts`, `items`, `issues`, `blockers` и `batch`.
Для элемента проверь `state`, `candidate_sha256`, `published_sha256`,
`publication_source`, `acquisition_attempts`, `distinct_valid_hashes` и
`item_outcome`. Общий код завершения не заменяет `counts.effective_verified` и
`items[].effective_verified`. Для кандидата, полученного в пакете,
`candidate_sha256` должен совпасть с `published_sha256`; для переиспользованной
записи сверяй опубликованный SHA с исходным снимком владельца.

`batch run --rounds N` принимает `1..=5`; поколение ограничено пятью
автоматическими попытками на идентичность. Технически повреждённые байты и отказ
источника не становятся семантическим образцом. Повтор того же SHA подтверждает
воспроизводимость, без нового независимого голоса. Явное отклонение/повторное
получение создаёт новое поколение только затронутой идентичности; готовые соседи
сохраняются.

## Проверка и решение пользователя

Для неразрешённых элементов после автоматического лимита создай отчёт:

```bash
cargo run --locked --bin kanji-assets -- --output json batch review --batch-id <id>
```

`review_artifact` — локальный HTML в игнорируемом служебном каталоге. Передай его
пользователю с кратким JSON-контекстом. Проверь символ, текущий SHA, формат,
автоматический статус, попытки, различные кандидаты, ограниченные свидетельства
каждой попытки, агрегированные среднее/минимум/максимум/число и ближайшего
конкурента. Отчёт показывает все различные кандидаты; GIF сохраняет анимацию.
Перед действием перечитай `batch status`, исключая устаревший SHA.

Русский ответ должен однозначно относиться к идентичности и показанному SHA:

| Решение пользователя | Структурированное действие |
|---|---|
| `漢 - подтверждён` | `confirm` |
| `字 - артефакт битый` / «не тот иероглиф» | `reject` |
| Явная просьба получить другой кандидат без оценки текущего | `reacquire` |
| Неоднозначный/неполный ответ | Не меняй состояние; уточни идентичность или действие |

Одно решение одной идентичности за вызов:

```bash
cargo run --locked --bin kanji-assets -- --output json batch decide \
  --batch-id <id> --character 漢 --sha256 <current-sha256> \
  --action confirm --reason "пользователь подтвердил текущий кандидат"

cargo run --locked --bin kanji-assets -- --output json batch decide \
  --batch-id <id> --character 字 --sha256 <current-sha256> \
  --action reject --reason "пользователь указал, что это другой иероглиф"
```

`confirm`, `reject`, `reacquire` требуют текущий `--sha256` и явный `--reason`.
Подтверждение не обходит формат, декодирование, целостность и границы путей;
владелец отдельно хранит автоматическое решение и свидетельство человека по
идентичности/хешу. Отклонение человеком действует против прежнего `VERIFIED`.
При изменении байтов старое решение отвергается; это семантическое решение,
а не криптографическая подпись.

После `confirm` проверь `batch status` и итоговое доверие владельца. Прерывание
между сохранением решения и записью в канонический корпус продолжай `batch run`
с тем же ID: используются сохранённые байты без нового браузерного получения.
После `reject` запусти `run` для обновлённого набора; если элемент не разрешён,
создай новую версию отчёта.

Если пять технических отказов не оставили кандидата, начни явное новое поколение:

```bash
cargo run --locked --bin kanji-assets -- --output json batch retry --batch-id <id> \
  --character 字 --reason "источник снова доступен"
```

При существующем кандидате используй `batch decide --action reacquire` с его
SHA вместо `retry`.

## Локальное состояние корпуса

Корпус кандзи — локальное доверенное состояние в `.asset-store/kanji`: он не
публикуется через Git, отдельных ветвей публикации ресурсов и проверки прав
администратора для ресурсов не существует. До продвижения заметок повтори
`kanji-assets --output json list` и `batch status` и убедись, что все запрошенные
элементы разрешены: `items[].effective_verified = true`,
`counts.unresolved = 0`, `counts.pending_publication = 0`. Разница снимка по
идентичности/SHA/доверию должна относиться только к исходному набору пакета и
совпадать с `published_sha256`; посторонняя разница означает, что хранилище
изменилось помимо пакета, — сохрани состояние и разберись, не запуская новое
получение.

Проверка корпуса запускается текущим кодом из корня checkout:

```bash
cargo run --quiet --locked -p asset-store --bin kanji-corpus-gate
```

Её отказ означает, что не все записи корпуса проверены; корпус с неподдерживаемой
схемой не понижай вручную. После возобновления повтори именно кандзи `list` и
проверку корпуса; сохрани независимые идентичности и точные SHA/доверие пакета.

## Продвижение карточек

После раунда, решения и повторного получения перечитай состояние и продвигай
заметки, у которых разрешены **все** зависимости. Выполни полный dry-run
`anki-repo create`, затем применяй только готовые заметки. Запросы, GUID и
результаты сохраняй вне `decks/**` и Git. Снимок «до» создай до первого
`--apply`; после записи — `validate` и `visual-report` с явными `--before`
и `--after`, вне `decks/**`. Повтор должен сходиться к no-op без дубликатов.
